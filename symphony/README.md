## 🎯 Applicable Projects

**Universal — any project, any stage.** No modes. SDD assesses context and runs one flow; only the enforcement strictness changes.

| Type | What SDD does | Gate level |
|---|---|---|
| **New** | Runs the flow; nothing to preserve | standard |
| **Early / In-progress** | Adds a Step 0 survey before changing code | standard |
| **Legacy / Maintenance** | Survey + regression to preserve behavior | standard |
| **Production** | Same flow; gates become non-bypassable | **strict** |

→ Production is **not blocked** — detecting production signals raises the enforcement level instead. Legacy is supported but not prioritized.

## 🚀 How to Use

### Step 0: Install spec-kit (prerequisite — this package leverages it)

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
```

### Step 1: Place the Files

```bash
# Copy the methodology files into your project root
cp symphony/AI-INTERVIEW.md ./
cp symphony/AI-EXECUTION.md ./
cp symphony/ORCHESTRA-GUIDE.md ./
cp symphony/INTEGRATION-CHECKLIST.md ./
```

### Step 2: Git Safety Net (optional, recommended)

```bash
git checkout -b feat/ai-integration
git add *.md
git commit -m "docs: add Spec-Driven Orchestra package (pre-run)"
```

### Step 3: Hand It to Claude Code

```bash
claude
```

Send this message:

```
Read AI-INTERVIEW.md and start.
Assess the context, run `specify init`, install the enforcement gates, then proceed with SDD.
```

### Context Additions (not modes)

The same flow; SDD adds steps based on what it finds — no `MODE_*` to pick:

```
Existing code present
  └─ survey.md      added: understand before changing
  └─ regression.md added: preserve existing behavior (R4)

Production signals detected
  └─ ENFORCEMENT_LEVEL=strict — tests/regression non-bypassable (R6)

Greenfield
  └─ same flow & gates; nothing to preserve, so they pass easily
```

Plus the enforcement layer (installed from `enforcement/`):
```
.claude/hooks/pre-implement.sh   # R1,R2 — no code without spec+plan
.claude/hooks/post-task.sh       # R5 — warn on missing handoff
.git/hooks/pre-commit            # R3,R4,R6 — no commit without passing tests
.github/workflows/sdd-gate.yml   # R1,R3,R6,R7 — non-bypassable merge gate
```

## ⚠️ Cautions

### 1. Production → Strict Gates (not blocked)

This package applies to production projects, but raises enforcement to strict:
- Detected automatically (deploy configs, `.env.production`, etc.)
- Tests and regression become mandatory and non-bypassable (R6)

### 2. Safety

- Existing assets → backed up to `archive/` (not deleted)
- Global settings → never touched
- Git-trackable → rollback anytime

### 3. Answer Honestly in the Assessment

- If the AI's read of the context is wrong → correct it directly
- For questions you don't know → choose "not sure" (AI uses a sensible default)
- The enforcement level can be adjusted after answering

## ❓ FAQ

### Q: I don't know whether it applies as new / legacy / production.
A: Just start. There's no mode to pick. SDD reads the context and runs one flow, auto-adjusting only the gate strictness.

### Q: The assessment feels burdensome.
A: It's 5-7 questions, each with an AI-recommended answer — you can just reply "yes".

### Q: I want to apply it to a production project.
A: You can. When production signals are detected, the enforcement level rises to strict so tests and regression become mandatory and non-bypassable.

### Q: I want to stop during integration.
A: Roll back instantly with Git:
```bash
git reset --hard HEAD~1
```
